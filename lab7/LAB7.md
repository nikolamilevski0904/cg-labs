# Lab 7 - Picking and dragging with THREE.Raycaster

In `lab7/main.js` the pointer -> NDC conversion lives in `updatePointer(event)`: it reads `renderer.domElement.getBoundingClientRect()`, subtracts `rect.left`/`rect.top` from `clientX`/`clientY` to get canvas pixels, and writes `x = 2*px/rect.width - 1` and `y = 1 - 2*py/rect.height` into the `pointerNDC` Vector2 (it uses the CSS size of the rect, not `canvas.width`, and flips y because NDC points up). `pickAt(event)` then calls `raycaster.setFromCamera(pointerNDC, camera)` and `intersectObjects(scene.children, true)`; only meshes on the `PICKABLE` layer can be hit, so the floor and grid are ignored. The ray-plane intersection is applied in `pointOnFloor(event)`, which calls `raycaster.ray.intersectPlane(floor, hitPoint)` for the plane `floor = Plane((0,1,0), 0)`; it solves `t = (d - n.o) / (n.d)` for the ray `o + t*d` and returns `null` when the ray is parallel to the plane (n.d = 0) or points away from it (t < 0), in which case the `pointermove` handler leaves the object where it is, and otherwise only `x` and `z` are updated (plus the `grabOffset` stored on `pointerdown`). The OrbitControls conflict is solved in the `pointerdown` handler: when the click hits a mesh it sets `controls.enabled = false` (and calls `setPointerCapture`), and `pointerup` sets `controls.enabled = true` again; the listener is registered before `new OrbitControls(...)` so it runs first, and a click on empty space leaves the controls enabled so the camera orbits normally.
